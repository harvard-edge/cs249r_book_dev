Preface

Who This Book Is For

This book is for students, researchers, and systems engineers who understand foundational machine learning infrastructure and now need to architect systems that pursue complex goals through repeated observation, reasoning, and environmental actuation. It bridges the gap between an isolated agent demonstration and a deployed system that must preserve state, respect authority boundaries, survive partial failure, and produce evidence of task completion.

The expected reader is familiar with single-machine ML systems (kernel optimization, hardware rooflines) and distributed systems (fleet-scale training and serving). Familiarity with computer architecture, operating systems, networking, or database transactions is helpful, but the text develops all necessary systems abstractions from first principles as they become relevant.

Why an Agentic Systems Textbook

A reasonable engineer might look at the current wave of autonomous AI demonstrations and ask a skeptical question: Is “Agentic ML Systems” a genuine, rigorous systems engineering discipline with durable principles—like operating systems, distributed systems, and computer architecture—or is it merely an ephemeral collection of Python wrappers, prompt-engineering hacks, and API glue?

The skepticism is justified. In contemporary artificial intelligence, immense attention is paid to surface styling: transient framework abstractions, conversational personas, prompt templates, and ten-line Python loops that look impressive in canned demos but fall apart under production workloads. Every road vehicle, from a lightweight sports car to a commercial haul truck, looks different on the surface. Yet underneath varied body styling, every vehicle shares the same physical invariants: a powertrain to convert energy into force, a transmission to manage torque, steering and brakes to direct momentum, a chassis to absorb load, and tires where rubber meets the road.

This book teaches how to design, measure, and govern machine learning systems that act over time. Its central problem is how to carry a delegated task from a stated goal to an accepted outcome while controlling what the system may observe and change, preserving state across interruptions, and gathering evidence of completion. The trajectory is the unit of engineering that connects these decisions. Readers should leave able to decide when a fixed workflow suffices, when a model-directed loop earns its added cost, and what authority, recovery, and evaluation that loop requires.

A traditional machine learning inference request maps an input tensor to an output prediction. The request is stateless, runs in milliseconds, incurs zero external side effects, and resets its memory the moment generation completes. An agentic system, by contrast, embeds that inference invocation inside a long-running, closed-loop control system that maintains persistent state, navigates non-deterministic decision spaces, and actuates external software and physical environments.

The moment an AI system takes actions across time, the failure modes cease to be questions of prompt syntax and become classic computer systems challenges:

  • How do you isolate untrusted code execution generated by an unprivileged model?
  • How do you manage memory residency across finite context windows and high-bandwidth accelerator memory when requests pause for minutes awaiting tools?
  • How do you recover from partial failure across non-atomic external APIs when database Two-Phase Commit is impossible?
  • How do you schedule concurrent, long-lived trajectories without starving serving clusters or deadlocking shared filesystems?

These are not prompt engineering problems. They are operating system problems, distributed systems problems, memory hierarchy problems, and compiler problems.

We approach this domain through the enduring lens of computer systems architecture in the tradition of Hennessy and Patterson. When a foundation model is deployed inside a multi-turn, stateful control loop, the machine that executes it is a Stochastic Computer. The foundation model is simply the stochastic processor core—an unprivileged execution unit that evaluates tokens and proposes candidate actions. Everything that makes the system dependable, secure, recoverable, and economically viable must be engineered into the computer system built around it.

The fundamental execution unit of this machine is not an isolated inference request; it is a managed trajectory—a bounded, stateful sequence of observations, latent deliberations, external actions, and verification steps directed toward an objective. Four governing systems dimensions define this architectural space:

  • Horizon: How far may execution proceed before the system must pause, verify, or seek external intervention?
  • State: What information persists across turns, in which tier of the memory hierarchy does it reside, and which copy is authoritative?
  • Authority: What environmental side-effects may the system commit, under what sandboxing boundaries, and with what mechanisms for containment or rollback?
  • Closure: How does the system deterministically verify completion evidence against ground truth rather than relying on the model’s verbal claims of success?

The Mental Model: The Stochastic Computer Architecture

To ground the systems engineering of autonomous agents, table 1 establishes the Architectural Rosetta Stone, mapping classical computer engineering subsystems directly to their counterparts in agentic machine learning systems. While the computational core is probabilistic rather than deterministic, the foundational challenges of systems design—memory bandwidth bottlenecks, virtual memory translation, interrupt handling, peripheral bus protocols, security rings, and profile-guided compilation—remain invariant.

Tying this entire architecture together is the Trajectory: the unifying system bus and execution stream that carries tokens, activations, memory pointers, tool payloads, checkpoint descriptors, and reward signals across the subsystems.

What This Book Covers

The book guides the reader through the Stochastic Computer architecture across seven dedicated parts:

  • Part I: The Stochastic Processor analyzes the autoregressive foundation model as an unprivileged, probabilistic compute core (the neural ALU), examining decoding dynamics under physical memory bandwidth limits, speculative execution, and test-time deliberation algorithms that scale inference compute.
  • Part II: Context Memory & Storage tackles the memory wall of stateful agents, establishing a three-tier memory hierarchy: L1 active attention working sets and compaction, L2 virtual context memory with non-contiguous PagedAttention and prefix sharing, and L3 episodic retrieval stores.
  • Part III: Tool Actuation & I/O Peripherals develops the interface between neural logits and external software environments, covering typed tool protocols (Model Context Protocol), actuation idempotency contracts, and hardware-virtualized sandboxing (Firecracker microVMs, WebAssembly, and Copy-on-Write filesystems).
  • Part IV: The Agent Operating System treats the runtime executive that keeps long-running trajectories dependable, including the Agent Control Block (ACB), durable state checkpointing with Write-Ahead Logs and distributed Sagas, asynchronous signal handling, and fair-share trajectory scheduling.
  • Part V: The Policy Compiler examines how empirical execution traces are compiled back into model weights, formalizing synthetic data flywheels, supervised fine-tuning with observation loss masking, and reinforcement learning with verifiable reward environments (RLVR/GRPO).
  • Part VI: The Distributed Fleet scales agent systems to clusters of cooperating entities, investigating multi-agent topologies and consensus, distributed OpenTelemetry trajectory tracing, and the macro-tokenomics of accelerator fleet sizing.
  • Part VII: System Synthesis culminates in an end-to-end production capstone, uniting every invariant and architectural boundary into a complete reference architecture, evaluating the limits of digital agency, and exploring the frontier of embodied physical systems.

The book is bracketed by Foundations of Agentic Systems, which establishes the whole-system closed-loop trajectory architecture and the Stochastic Computer paradigm, and Architectural Synthesis, which provides the capstone synthesis and safety case.

A Note on Durability

Frameworks, Python libraries, prompt engineering tricks, and specific foundation model weights will inevitably evolve. The text therefore emphasizes the fundamental principles and physical constraints that survive these transitions: state ownership, memory bandwidth roofs, isolation boundaries, scheduling under non-deterministic latency, transactional consistency, and profile-guided feedback loops. Current open protocols and industry runtimes are used throughout to illustrate these concepts, but the architectural principles stand independently of any specific vendor or tool.

Prerequisites

Readers should be comfortable with:

  • machine learning training and inference pipelines (transformer architectures, attention mechanisms, backpropagation);
  • distributed systems concepts (concurrency, remote procedure calls, failure modes, consistency);
  • basic computer systems fundamentals (memory hierarchies, caches, virtual memory, process isolation); and
  • programming in Python or a modern systems language.
