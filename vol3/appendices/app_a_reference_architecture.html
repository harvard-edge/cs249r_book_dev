Reference Architecture

Throughout this book, agentic machine learning systems are analyzed through the conceptual lens of the Stochastic Von Neumann Architecture. This appendix translates those theoretical abstractions into a concrete, open-source production deployment stack. Systems architects and infrastructure engineers will find operational specifications, interface contracts, hardware sizing models, and deployment topologies spanning the stochastic processor, volatile key-value cache allocators, actuation sandboxes, durable workflow orchestrators, episodic retrieval tiers, and crash-consistent write-ahead logging pipelines.

How to Use This Appendix

This appendix serves as a systems reference manual for constructing and hardening production agent runtimes. Readers should consult specific sections based on the operational or architectural challenges encountered during design and deployment:

  • When selecting or sizing model inference engines and volatile memory allocators: Consult section 1.2 for GPU memory layouts, PagedAttention block tables, Radix tree prefix caching, TensorRT-LLM compilation, and key-value cache sizing arithmetic.
  • When isolating tool execution and mitigating untrusted environment mutations: Consult section 1.3 for Linux KVM virtualization, Firecracker microVM startup budgets, copy-on-write snapshotting, gVisor syscall interception, and WebAssembly capability sandboxing.
  • When architecting agent working sets, cyclic execution graphs, and durable workflows: Consult section 1.4 for context compaction pipelines, LangGraph state machines, LlamaIndex node schemas, and Temporal event-sourced distributed sagas.
  • When designing multi-tier episodic memory and working state stores: Consult section 1.5 for vector indexing trade-offs (HNSW vs. IVF-PQ), Redis working-set cache eviction, and bi-temporal audit ledgers.
  • When instrumenting distributed telemetry and engineering crash-consistent recovery: Consult section 1.6 for OpenTelemetry semantic conventions, W3C trace context propagation across microVM boundaries, and NVMe-backed write-ahead logging (WAL) protocols.
  • When deploying the complete reference stack across Kubernetes node pools: Consult section 1.7 for cluster topology blueprints, zero-trust egress network controls, and the production failure mode mitigation matrix.

The Stochastic Von Neumann Stack: Conceptual to Concrete

In Foundations of Agentic Systems, the agentic runtime was formalized as a non-deterministic computer operating under systems principles established by classical computer architecture (Neumann 1945). To build production systems, infrastructure engineers must map each conceptual subsystem to hardened, open-source software frameworks. Table 1 establishes this operational translation, detailing the physical implementations, primary systems invariants, and hardware bottlenecks governing each architectural layer.

Neumann, John von. 1945. First Draft of a Report on the EDVAC. Moore School of Electrical Engineering, University of Pennsylvania.

The physical integration of these layers is shown in figure 1. A production agentic runtime does not execute as an unconstrained loop on a single host. Instead, it operates as a distributed system partitioned across specialized compute, memory, and actuation boundaries.

The Stochastic Processor and Volatile Memory

In classical systems, the Central Processing Unit (CPU) executes deterministic machine code instructions against dynamic random-access memory (DRAM). In an agentic system, the processor core consists of an autoregressive transformer foundation model, while High-Bandwidth Memory (HBM) on the accelerator functions as volatile working memory. The primary systems constraint governing this layer is not arithmetic compute capacity during generation, but memory bandwidth and memory capacity bottlenecks imposed by the Key-Value (KV) cache.

Modern inference engines: vLLM, RadixAttention, and TensorRT-LLM

Production architectures require specialized serving engines to maximize throughput and eliminate memory waste:

  1. vLLM and PagedAttention: Classical inference allocators assign contiguous virtual memory spaces sized to the model’s maximum possible sequence length (\(S_{\max}\)). Because real-world agent trajectories exhibit variable sequence lengths, this produces severe memory fragmentation (often exceeding 60 to 80 percent wasted HBM). vLLM resolves this bottleneck by implementing PagedAttention (Kwon et al. 2023), which partitions the KV cache into fixed-size logical blocks (typically 16 or 32 tokens) mapped dynamically to physical memory frames via page tables, analogous to operating system virtual memory paging. By eliminating external fragmentation and bounding internal fragmentation to the final block, vLLM increases batching concurrency by a factor of two to four within identical HBM budgets.
  2. SGLang and RadixAttention: While PagedAttention manages paging for linear requests, agentic execution is inherently tree-structured. Multi-turn reasoning, tool output observation cycles, and Monte Carlo Tree Search (MCTS) branches share extensive common prefixes. SGLang introduces RadixAttention (Zheng et al. 2024), which maintains the KV cache as a Radix tree (trie) data structure directly in host and accelerator memory. When a new trajectory turn or speculative branch arrives, the runtime matches the longest prefix in the Radix tree, bypassing redundant prefill computation. Unused cache pages are retained until memory pressure triggers an eviction algorithm based on Least Recently Used (LRU) policies with recursive reference counting.
  3. TensorRT-LLM: Engineered for maximum bare-metal throughput on NVIDIA architectures, TensorRT-LLM compiles model graphs into optimized execution runtimes using TensorRT. It employs static kernel fusion, custom FlashAttention-2 kernels (Dao 2023), in-flight batching (also known as continuous iteration-level scheduling), and specialized multi-GPU communications over NVLink. While TensorRT-LLM yields the lowest per-token latency for fixed-shape production workloads, its static compilation model makes dynamic Radix tree modifications more complex compared to SGLang.
Kwon, Woosuk, Zhuohan Li, Siyuan Zhuang, Ying Sheng, Lianmin Zheng, Cody Hao Yu, Joseph Gonzalez, Hao Zhang, and Ion Stoica. 2023. “Efficient Memory Management for Large Language Model Serving with PagedAttention.” Proceedings of the 29th Symposium on Operating Systems Principles, 611–26. https://doi.org/10.1145/3600006.3613165.
Zheng, Lianmin, Liangsheng Ying, Zhenghao Yin, Cody Hao Liu, Eric Yu, Prakhar Patel, Zhipeng Yang, Anthony K. Joseph, and Ion Stoica. 2024. “SGLang: Efficient Execution of Structured Language Model Programs.” arXiv Preprint arXiv:2312.07104, ahead of print. https://doi.org/10.48550/arXiv.2312.07104.
Dao, Tri. 2023. “FlashAttention-2: Faster Attention with Better Parallelism and Work Partitioning.” arXiv Preprint arXiv:2307.08691.

Key-value cache sizing arithmetic and memory budgets

To prevent out-of-memory (OOM) faults during deep trajectory exploration, systems architects must calculate the exact physical memory footprint of the model parameters and its backing KV cache. For a model with \(L\) transformer layers, \(H_{\text{KV}}\) key-value attention heads, head dimension \(D_{\text{head}}\), floating-point byte precision \(P_{\text{bytes}}\) (e.g., 2 bytes for FP16/BF16, 1 byte for FP8), sequence length \(S\), and concurrent batch size \(B\), the required KV cache memory \(M_{\text{KV}}\) in bytes is governed by:

\[M_{\text{KV}} = 2 \times L \times H_{\text{KV}} \times D_{\text{head}} \times P_{\text{bytes}} \times S \times B\]

The leading factor of 2 accounts for storing both key and value tensors. Consider a production deployment of a 70-billion parameter model utilizing Grouped-Query Attention (GQA):

  • Number of layers: \(L = 80\)
  • Key-Value heads: \(H_{\text{KV}} = 8\)
  • Head dimension: \(D_{\text{head}} = 128\)
  • Precision: \(P_{\text{bytes}} = 2\) (BF16)

Evaluating the per-token memory allocation yields:

\[\text{Memory per token} = 2 \times 80 \times 8 \times 128 \times 2 = 327{,}680\text{ bytes} \approx 327.68\text{ KB/token}\]

Across an agent trajectory carrying an accumulated working context of \(S = 32{,}768\) tokens, a single agent session consumes:

\[M_{\text{KV},\text{session}} = 327{,}680 \times 32{,}768 \approx 10.74\text{ GB of HBM}\]

On an 80 GB NVIDIA H100 SXM5 GPU, model weights in 8-bit quantization (FP8) consume approximately 70 GB. A single GPU cannot hold the model weights and even two concurrent 32K agent sessions without exhausting HBM. Consequently, production deployments require partitioning across multi-GPU nodes using Tensor Parallelism (TP = 2 or TP = 4) to pool HBM capacity, or offloading inactive KV pages across PCIe Gen5 buses to host DDR5 memory as detailed in Paged Attention Memory.

Actuation and Environment Sandboxing

Classical computer architectures maintain system integrity by enforcing hardware-level privilege separation: user-space applications run in Ring 3, whereas the operating system kernel runs in Ring 0. When user applications require hardware operations, they must execute an explicit hardware trap instruction (such as SYSCALL), transferring control to the kernel.

In an agentic system, the stochastic processor generates tokens that represent operational commands. As established in Foundations of Agentic Systems, the transformer architecture violates the classical \(W \oplus X\) (Write XOR Execute) protection invariant: instructions (system prompts) and untrusted data (tool observations, user payloads, retrieved web pages) share an identical token stream processed by the same attention weights. Because prompt injection is an inevitable consequence of this unified token representation, security boundaries cannot be enforced via prompting. The actuation layer must enforce complete mediation (Saltzer and Schroeder 1975) through external isolation sandboxes.

Saltzer, J. H., and M. D. Schroeder. 1975. “The Protection of Information in Computer Systems.” Proceedings of the IEEE 63 (9): 1278–308. https://doi.org/10.1109/proc.1975.9939.

Sandboxing technologies: MicroVMs, containers, and WebAssembly

Production environments deploy three distinct tiers of execution sandboxing, balancing security isolation against startup latency:

  1. Firecracker MicroVMs: Developed by Amazon Web Services, Firecracker uses the Linux Kernel-based Virtual Machine (KVM) interface (/dev/kvm) to launch minimalist virtual machines (Agache et al. 2020). Firecracker strips away legacy PC peripherals, emulating only basic virtio devices (virtio-net, virtio-block, virtio-vsock) and a minimal serial console. Each microVM process is managed by an unprivileged jailer process that executes a chroot jail, creates isolated Linux namespaces (PID, NET, IPC, UTS), enforces cgroups v2 resource quotas, and applies an aggressive seccomp-bpf filter that drops all non-essential system calls. Through copy-on-write (CoW) memory snapshotting, a pre-warmed Firecracker microVM restores in under 5 ms with a baseline memory footprint of roughly 5 MB, providing hardware-level hardware virtualization security.
  2. gVisor Container Sandboxing: Classical OCI containers (such as Docker or runc) share the host Linux kernel directly, relying purely on namespaces and cgroups. If an agent executes an untrusted script that exploits a host kernel vulnerability (such as privilege escalation via CVE-2024-21626), the container escapes to the host. gVisor resolves this by running a dedicated user-space kernel called Sentry (Google 2019). Sentry intercepts application system calls via ptrace or KVM virtualization, implementing core Linux kernel semantics entirely in memory-safe Go. System calls never reach the host kernel directly; file and network I/O are mediated by a separate Gofer process. This design provides robust defence-in-depth at the cost of elevated I/O syscall latency.
  3. WebAssembly (Wasmtime): For deterministic compute tasks—such as executing mathematical routines, running data transformations, or parsing JSON/XML schemas—virtual machine startup overhead is unnecessary. WebAssembly runtimes like Wasmtime provide capability-based security through the WebAssembly System Interface (WASI). A Wasm module runs inside an isolated linear memory space with zero default access to the host filesystem, environment variables, or network sockets. Modules instantiate in under 50 microseconds with memory overheads below 1 MB.
Agache, Alexandru, Marc Brooker, Andreea Florescu, Alexandra Iordache, Anthony Liguori, Rolf Neugebauer, Phil Piwonka, and Diana-Maria Popa. 2020. “Firecracker: Lightweight Virtualization for Serverless Applications.” Proceedings of the 17th USENIX Symposium on Networked Systems Design and Implementation (NSDI 20), 419–34.
Google. 2019. gVisor: Container Runtime Sandbox.

Working Sets and Durable Orchestration

In classical operating systems, the kernel schedules processes, maintains execution threads, and preserves execution context across hardware interrupts. In agentic infrastructure, this role is filled by working set governors and durable orchestration engines.

Context working set management

An agent’s working context cannot expand indefinitely. Beyond the physical HBM limits analyzed in section 1.2, attention mechanisms suffer from performance degradation when irrelevant tokens accumulate (the Context Accumulation Wall, Foundations of Agentic Systems). Production runtimes implement active working set management:

  • Token Budget Governors: The working context is partitioned into rigid allocation budgets: 10 percent reserved for system invariants and tool definitions, 40 percent allocated to active retrieval and episodic memory, 30 percent dedicated to sliding dialogue and tool outputs, and 20 percent reserved for speculative chain-of-thought generation.
  • Attention Sink Anchoring: Based on the StreamingLLM discovery (Xiao et al. 2024), autoregressive models assign massive attention scores to the initial tokens of a sequence regardless of their semantic content. Runtimes pin the initial 4 to 8 tokens (attention sinks) permanently in the KV cache, preventing attention map collapse when sliding-window eviction is applied to historical turns.
  • Hierarchical Compaction: When observation tokens threaten the context budget, deterministic summarization pipelines compress verbose terminal logs, compiler traces, and file contents into compact structural skeletons before re-injecting them into the prompt stream (Working Context).
Xiao, Guangxuan, Yuandong Tian, Beidi Chen, Song Han, and Mike Lewis. 2024. “Efficient Streaming Language Models with Attention Sinks.” International Conference on Learning Representations (ICLR).

Durable execution with temporal and distributed Sagas

A common failure mode in naive agent prototypes is the unconstrained Python loop (while not done:). If the host process crashes, the host machine reboots, or an API call times out mid-trajectory, the agent’s internal state is permanently lost. Furthermore, if an agent successfully charges a credit card, books a flight, and subsequently fails while booking a hotel, simple retries result in duplicate charges or inconsistent real-world states.

Production agent architectures deploy Temporal (or Cadence) as their durable execution engine:

  1. Event Sourcing and Deterministic Replay: Temporal persists every state transition, tool dispatch, and timer event to an append-only database (PostgreSQL, Cassandra, or MySQL). If an orchestration worker crashes mid-trajectory, a replacement worker rehydrates the exact internal state by replaying past execution events deterministically, eliminating state corruption.
  2. Asynchronous Human-in-the-Loop Pauses: When an agent requires human authorization to execute a privileged mutation, Temporal suspends the workflow state durably without consuming CPU cycles or memory threads, resuming execution seamlessly hours or days later upon receiving an external signal.
  3. The Distributed Saga Pattern: Because external environment mutations (such as creating cloud instances, committing database updates, or dispatching webhooks) lack distributed two-phase commit (2PC) transactions, agents must structure execution as a Saga (Gray 1981). Every forward action \(A_i\) must be paired with an idempotent compensating action \(C_i\):
Gray, Jim. 1981. “The Transaction Concept: Virtues and Limitations.” Proceedings of the Seventh International Conference on Very Large Data Bases (VLDB) 7: 144–54.

\[\text{Forward Sequence: } A_1 \to A_2 \to \dots \to A_k \quad \xrightarrow{\text{Failure at } A_k} \quad \text{Compensating Rollback: } C_{k-1} \to \dots \to C_2 \to C_1\]

If action \(A_k\) fails and cannot be recovered via retries, the orchestrator halts forward execution and invokes compensating routines in reverse order, restoring the external environment to a consistent baseline.

Episodic Memory and Persistent State

Because volatile GPU memory is bounded and costly, an agent runtime must offload long-term state to persistent storage. Analogous to the storage hierarchy of a computer system (registers \(\to\) L1/L2 cache \(\to\) DRAM \(\to\) NVMe SSD \(\to\) Cold Object Store), an agent manages a multi-tier memory hierarchy.

Vector indexing topologies: HNSW vs. IVF-PQ

Unstructured episodic memory relies on high-dimensional vector representations generated by embedding models. When searching over millions of historical trajectory chunks, exact nearest neighbor search requires an exhaustive linear scan of computational complexity \(O(N \cdot D)\), which introduces unacceptable latency. Production systems use Approximate Nearest Neighbor (ANN) indexing:

  1. Hierarchical Navigable Small World (HNSW): HNSW constructs a multi-layer geometric proximity graph (Malkov and Yashunin 2020). Upper layers contain sparse, long-range skip edges that route queries across the vector space with logarithmic search complexity \(O(\log N)\). Lower layers transition into dense proximity graphs for local convergence. HNSW delivers outstanding recall (often exceeding 95 to 98 percent) and sub-10 millisecond search latencies. However, because HNSW maintains high-degree graph edges and unquantized floating-point vectors in host memory, it requires approximately 1.5 to 2.0 KB of DRAM per 1536-dimensional vector, making billion-scale deployments memory-intensive.
  2. Inverted File Product Quantization (IVF-PQ): IVF-PQ combines coarse spatial clustering with lossy vector compression (Jégou et al. 2011). The vector space is partitioned into \(K\) Voronoi cells using \(k\)-means centroids. High-dimensional residual vectors are then sliced into \(M\) sub-vectors, each quantized to the nearest centroid in an 8-bit codebook. At query time, Asymmetric Distance Computation (ADC) computes distances using precomputed lookup tables without decompressing stored vectors. IVF-PQ compresses vector storage footprints by 90 to 95 percent, enabling billion-vector datasets to reside within modest RAM footprints at the expense of lower recall (80 to 90 percent) and higher build indexing latency.
Malkov, Yury A., and Dmitry A. Yashunin. 2020. “Efficient and Robust Approximate Nearest Neighbor Search Using Hierarchical Navigable Small World Graphs.” IEEE Transactions on Pattern Analysis and Machine Intelligence 42 (4): 824–36. https://doi.org/10.1109/TPAMI.2018.2889473.
Jégou, Hervé, Matthijs Douze, and Cordelia Schmid. 2011. “Product Quantization for Nearest Neighbor Search.” IEEE Transactions on Pattern Analysis and Machine Intelligence 33 (1): 117–28. https://doi.org/10.1109/TPAMI.2010.57.

Production architectures deploy Milvus or Qdrant with hybrid indexing: recent, active trajectory memories are indexed in high-recall HNSW graphs, while older historical records are archived into compressed IVF-PQ segments.

Observability, Checkpointing, and Auditability

In single-turn model serving, monitoring consists of tracking request latency, token throughput, and HTTP 5xx error rates. In an agentic system, operational failures manifest as semantic loops, unhandled tool exceptions, privilege violations, and cascading hallucinations. To debug and govern autonomous systems, infrastructure must implement distributed observability and crash-consistent write-ahead logging.

OpenTelemetry for distributed agent trajectories

Because an agent trajectory fans out across inference clusters, workflow engines, and sandboxed microVMs, observability requires standardized distributed tracing. The open-source standard for this instrumentation is OpenTelemetry (OTel):

  • Trace Context Propagation: Trajectories establish a root trace span. As the agent invokes asynchronous tool calls or delegates sub-tasks to child agents, the runtime injects the W3C TraceContext headers (traceparent, tracestate) across HTTP, gRPC, and microVM vsock boundaries, ensuring that every tool invocation links back to its parent reasoning step.
  • Semantic Conventions for Generative AI: Telemetry pipelines adhere to established OpenTelemetry GenAI semantic conventions, recording standardized attributes across every inference call: gen_ai.system (e.g., vllm), gen_ai.request.model, gen_ai.usage.prompt_tokens, gen_ai.usage.completion_tokens, and gen_ai.response.finish_reasons.
  • Tool Actuation Spans: Runtimes wrap tool dispatches with custom spans capturing tool names, JSON input parameter hashes, execution durations, exit codes, and byte counts of stdout/stderr outputs.

Write-ahead logging (WAL) on high-performance NVMe

To guarantee crash consistency across host restarts and catastrophic hardware faults, the agent runtime enforces the Agent Write-Ahead Log Invariant (Persistent Storage):

\[\text{Commit}(\mathcal{L}_{\text{WAL}}, \langle \text{seq}, t, s_t, a_t, \text{nonce} \rangle) \prec \text{Dispatch}(a_t, \text{Sandbox})\]

The runtime must never dispatch an operational action \(a_t\) across the actuation boundary until the proposed action record and current state belief \(s_t\) have been durably persisted to an append-only log on non-volatile storage. Figure 2 gives the byte-exact frame that carries this record. The leading magic identifier and sequence number let a recovery pass locate frame boundaries in a partially written log, the state hash binds the record to the belief it was written under, and the trailing CRC32-C checksum is what distinguishes a torn write from a complete one.

WAL write operations bypass the operating system page cache using direct I/O (O_DIRECT) and issue explicit fdatasync barriers to enterprise NVMe solid-state drives. Modern enterprise NVMe drives (such as PCIe Gen5 U.2/E1.S SSDs) achieve sequential fsync commit latencies under 80 microseconds, introducing negligible overhead relative to the hundred-millisecond inference generation times of the stochastic processor.

Production Deployment Blueprint and Failure Modes

Deploying an agentic platform in production requires partitioning hardware resources across specialized Kubernetes node pools to isolate distinct performance and security profiles.

Kubernetes infrastructure partitioning

A resilient deployment topology isolates workloads into four dedicated node pools:

  1. GPU Inference Pool (Accelerated Compute): High-density GPU nodes (e.g., 8x NVIDIA H100 SXM5 with NVLink). Nodes run containerized inference servers (vLLM or SGLang) with memory-locked HBM allocations, pinned CPU cores, and SR-IOV network interfaces configured for RoCE v2 (remote direct memory access (RDMA) over Converged Ethernet) or InfiniBand interconnects.
  2. Orchestration & Workflow Pool (High-Reliability CPU): General-purpose compute nodes running Temporal server instances, LangGraph runtimes, and ingress controllers. Workloads are configured with aggressive pod disruption budgets (PDBs), redundant replicas across availability zones, and persistent volume attachments for local state.
  3. Sandboxed Worker Pool (Virtualization Nodes): Bare-metal compute instances equipped with hardware-assisted virtualization extensions (Intel VT-x or AMD-V) enabled. Standard cloud virtual machines cannot be used unless nested virtualization is explicitly supported. These nodes run the Firecracker jailer daemons and gVisor container runtimes, isolated from internal corporate networks.
  4. State & Storage Pool (High-IOPS Data Tier): Storage-optimized instances housing Redis clusters, Milvus query/data nodes, and PostgreSQL replicas backed by local PCIe Gen5 NVMe drives configured in redundant array of independent disks (RAID) 10.

Zero-trust network architecture and egress control

Because agents execute non-deterministic code capable of accessing external networks, network egress represents a critical vulnerability. Sandboxed execution environments must operate under a zero-trust network perimeter:

  • Default Egress Deny: All outbound network traffic from actuation sandboxes is blocked by default via Kubernetes NetworkPolicy and Linux iptables / nftables rules.
  • Transparent Egress Proxying: Sandboxes requiring external web access must route connections through an authoritative, terminating forward proxy (such as Envoy). The proxy enforces mutual TLS (mTLS), terminates SSL connections to inspect payloads for data exfiltration, restricts access to explicit domain allow-lists, and logs all network transactions to the telemetry pipeline.
  • Cryptographic SPIFFE/SPIRE Identities: MicroVM instances and subagent processes receive short-lived cryptographic identity x509 SVID tokens via SPIFFE/SPIRE, eliminating hard-coded API credentials and preventing unauthorized horizontal privilege escalation across subagents.

Summary

The reference architecture detailed in this appendix demonstrates that constructing robust agentic systems is fundamentally an exercise in systems engineering rather than prompt design. By grounding the Stochastic Von Neumann Architecture into concrete, open-source technologies—vLLM and SGLang for volatile memory management, Firecracker and gVisor for actuation isolation, Temporal for durable state orchestration, Redis and Milvus for episodic memory hierarchies, and OpenTelemetry and NVMe write-ahead logging for crash-consistent governance—engineers can transform non-deterministic foundation models into resilient, auditable, and secure enterprise software systems.
