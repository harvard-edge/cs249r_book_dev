Environment Variables

What you may change, and what changing it costs

Every knob below is read from the environment at run time. They exist so a researcher can explore the space around a contract, not so a result can be tuned into passing.

ImportantTwo categories, and the difference matters

Execution settings change how a workload runs without changing what it claims. Seed, device, and data location are in this group. A max result produced with a different device is still a max result.

Contract overrides change what the workload measures. Epochs, batch sizes, sequence lengths, iteration counts, and quality targets are in this group. A run with any of these set is a research variant, not a comparable max result, and the report records the override so a reviewer can see it.

If you are producing a result someone else will compare against, set nothing in the second group.

Execution Settings

These are safe to set for a comparable run.

Variable Meaning Default
MLPERF_EDU_SEED Seed for every stochastic path in the run 42
MLPERF_EDU_MAX_SEED Seed override consulted before MLPERF_EDU_SEED unset
MLPERF_EDU_DEVICE Force a torch device (auto, cpu, mps, cuda) auto-selected
MLPERF_EDU_DATA_DIR Where fetched datasets and checkpoints live project cache
MLPERF_EDU_QUIET Set to 1 to silence per-epoch training progress unset
MLPERF_EDU_NO_BROWSER Set to 1 to stop reports opening a browser unset
MLPERF_EDU_HF_LOCAL_ONLY Set to 1 to forbid Hugging Face network access unset

Training runs report epoch, metric, elapsed time, and an estimate of time remaining to stderr. MLPERF_EDU_QUIET=1 turns that off; it never affects the measured result.

MLPERF_EDU_MAX_QUALITY_TARGET deserves specific mention. It replaces the inherited quality target for causal language modeling. Lowering a target is the exact move the suite exists to prevent, so a run that sets it can never be score-bearing.

MLPERF_EDU_NCF_LEARNING_RATE and MLPERF_EDU_NCF_LR_SCHEDULE exist for one open question. The recommendation contract fixes Adam at a constant rate, HR@10 peaks early and then declines, and the upstream reference may anneal instead. Testing that requires varying the schedule without editing the contract, which is what the pro envelope is for. MLPERF_EDU_NCF_LR_SCHEDULE accepts constant (the contract behavior and the default), cosine, or step. Both variables reject malformed or non-positive values rather than falling back to the contract, because an override that silently does nothing would make an ablation look like a null result. Leaving both unset reproduces the canonical max path exactly.
