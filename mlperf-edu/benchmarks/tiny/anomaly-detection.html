tiny suite

experimental

Source-locked promotion rationale. Direct MLPerf Tiny ToyCar autoencoder and complete 248-recording accuracy-contract adaptation; claims remain withheld until committed repeated timing is complete. Current draft evidence is listed below.

Why This Benchmark Is Included

Canonical reconstruction-based industrial anomaly task.

Field Value

Adaptation boundary: Fused weights are read from the pinned MLCommons TFLite artifact and loaded into the equivalent PyTorch dense autoencoder. The fixed MLCommons index selects 248 recordings from the immutable ToyADMOS archive, and the pinned upstream librosa recipe generates the exact sliding-window inputs.

How to Run

# one-time asset preparation
uv run mlperf fetch --workload anomaly-detection --profile max

# benchmark run (writes JSON/HTML/CSV reports + .provd.json provenance)
uv run mlperf run --workload anomaly-detection --profile max

# quick smoke pass
uv run mlperf run --workload anomaly-detection --profile min

# research envelope
uv run mlperf run --workload anomaly-detection --profile pro

See the running guide for profile semantics, report handling, and power measurement flags.

  • The 0.85 ROC AUC threshold, ToyCar task, 248-recording index, feature recipe, and autoencoder are inherited from MLPerf Tiny.

  • Promotion still requires committed repeated timing evidence on the reference platform.

Results

To make the metric concrete, one run of this benchmark on Apple M5 Max observed roc_auc of 0.9029, taking 0.2838 inference_seconds.

That is an illustration, not a target and not a score. It comes from a single machine and your hardware will produce different timing. The number that matters is the one your own run reports.

Run the benchmark and read your own report:

uv run mlperf run --workload anomaly-detection --profile max

Every run writes an HTML dashboard for reading, JSON for machine use, CSV for spreadsheets, and a .provd.json provenance manifest. Those artifacts carry the quality decision, timing distribution, hardware and software fingerprint, asset digests, and model lineage for the run you performed.

See Reading Results for how to interpret them.
