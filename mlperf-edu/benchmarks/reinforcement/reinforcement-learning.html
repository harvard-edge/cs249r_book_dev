reinforcement-learning

reinforcement suite

Warning

Independent preview. MLPerf EDU is not an official MLCommons benchmark and is not endorsed by MLCommons. Registry result labels are candidate classifications for review, not accepted MLPerf result categories.

experimental

Readiness status. The max CLI preserves the full historical MiniGo quality loop and professional-game evaluator, and the PyTorch adapter executes it locally against the pinned upstream reference. Quality conformance remains open because the laptop budget runs far fewer self-play games per generation than the reference contract specifies, not because the runtime is unavailable. No draft reference result or public baseline is claimed for this workload.

Adaptation boundary: The min profile retains a bounded policy-value probe. The max profile invokes the pinned MLPerf Training v0.5 phase entrypoints with resumable orchestration and fails closed until an immutable compatible GPU runtime is supplied.

How to Run

# one-time asset preparation
uv run mlperf fetch --workload reinforcement-learning --profile max

# benchmark run (writes JSON/HTML/CSV reports + .provd.json provenance)
uv run mlperf run --workload reinforcement-learning --profile max

# quick smoke pass
uv run mlperf run --workload reinforcement-learning --profile min

# research envelope
uv run mlperf run --workload reinforcement-learning --profile pro

See the running guide for profile semantics, report handling, and power measurement flags.

Reviewer notes:

  • The target is the original 9-by-9 MLPerf Training MiniGo professional-move prediction gate.
  • The functional spiral performs a bounded policy-value self-play and training probe without making a MiniGo quality claim.
  • The recorded result is a reduced-configuration probe, not an attempt at the reference contract. It runs 16 self-play games per generation for 4 generations against a reference of 2000 games per generation and up to 10000 generations, so the shortfall is a property of the laptop budget rather than of the adapter. This is a different kind of miss from a workload that executes its full reference procedure and falls short, and it should not be read as evidence that the inherited gate is unreachable.

Results

Run the benchmark and read your own report:

uv run mlperf run --workload reinforcement-learning --profile max

Every run writes an HTML dashboard for reading, JSON for machine use, CSV for spreadsheets, and a .provd.json provenance manifest. Those artifacts carry the quality decision, timing distribution, hardware and software fingerprint, asset digests, and model lineage for the run you performed.

See Reading Results for how to interpret them.
